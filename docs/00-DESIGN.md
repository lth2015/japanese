# 设计稿 00 — 愿景与 V1 范围

> 这是一份个人使用的日语开口训练系统的设计文稿。不是 demo，不做 SaaS，只为一个真实用户（系统作者本人）服务。本文档基于 `README.md` 的 PRD，但会标注我建议的偏离与原因。

## 1. 目标定义

**一句话目标**：让一个 N1 阅读、却在日企会议里"看得懂但说不出口"的工程师，能在两个月内做到日常工作场景**自然开口**。

**衡量标准**（实证、可观察）：
- 工作日均**有效开口时长**（系统记录的录音 + 朗读总时长） ≥ 15 分钟
- **CN → JP 写作 drill** 成功率（系统判定"自然"或"商务可用"）从基线提升到 ≥ 70%
- 在真实会议中，**卡壳救援句**的命中数（"少し確認させてください" 等）从被动学习变为主动产出

> 注意：这些是**给自己看的指标**，不是 KPI 报表。系统应该在 Dashboard 直接显示这些数字，避免装饰性图表。

## 2. 与 README 的关键偏离（我建议这样改）

| README 原方案 | 我的建议 | 原因 |
|---|---|---|
| 30 天固定课程体系 | **删除**。替换为"场景库 + 个人语料本"。 | 你的真实会议/Slack/邮件**就是你的课程**。固定课程对个人用户毫无价值，会变成"今天又没完成 Day 14"的负担。 |
| CN → JP 训练用**语音回答** | **改为打字输入**（语音是第二选项）。 | 真正的瓶颈是**句子组织**（脑中构句），不是发音。打字才能逼你完整构句、改写、对照。语音 drill 留给跟读和对话模块。 |
| 跟读和对话的"发音评估"由 Gemini 完成 | **拆成两件事**：(1) STT 转写 + WER (Word Error Rate) = 发音准确度；(2) Gemini 只做"自然度 / 商务感"反馈。 | Gemini 拿到的只是 STT 出来的文本，它**根本看不到音频**，不可能评估发音。原方案技术上不成立。 |
| Display 模式（轮播）作为辅助功能 | **升级为第一公民**。Display 是这个系统的**杀手特性**。 | 对"职场被动接触"用户，第二屏挂机几小时 / 通勤路上盯手机的**累积曝光**比每天 5 分钟主动 drill 更有效。这是和市面所有日语 app 的核心差异。 |
| 错题复习用艾宾浩斯 | 用 **SM-2（间隔重复）**。配合"该项目仓库内已安装的 fluent skill 用的就是 SM-2"。 | SM-2 是经过 Anki 等系统多年验证的算法，参数比艾宾浩斯曲线更适合个体差异。复用已有 skill 的实现节省代码量。 |
| 数据库 MVP 用 Supabase，后续 PostgreSQL | **直接用 Supabase 留下**。 | 自带 Auth + Storage（录音文件）+ Postgres + Row Level Security，单用户场景完全够用。"后续迁移 RDS"是给真有规模时再做的，个人用根本不需要。AWS 部署里**只用 S3 当录音备份**就行。 |
| OAuth (Google / Apple) | **删除**。改为 magic link 或单一密码登录。 | 单用户系统，OAuth 是过度工程。 |
| NestJS 或 Next.js API | **Next.js Server Actions + Route Handlers**。 | 个人项目，单仓库最简单。NestJS 在这里是 dead weight。 |

## 3. V1 模块（4 个，不是 8 个）

| 优先级 | 模块 | 职责 | 核心交互 |
|---|---|---|---|
| **P0** | **Display 屏** `/display` | 给第二屏 / 手机挂机用的被动闪卡。全屏、大字、自动轮播。 | 用户配置队列 + 字号 + 间隔 + 是否朗读 TTS。其他时间它就静静地放着。 |
| **P0** | **写作 Drill** `/drill` | 中文 → 日语打字输入，AI 给出"更自然 / 商务版 / 口语版"三套对照。 | 显示中文 → 用户打字 → 提交 → AI 反馈 → 一键加入"我的语料本" |
| **P0** | **跟读** `/read` | 给一句日语 → 播放 TTS → 用户录音 → STT + WER → Gemini 自然度反馈。 | 播放、录音、对照、再录、加入复习队列 |
| **P1** | **对话** `/talk` | AI 扮演同事/上司，10 轮以内的语音对话，结束后给 transcript + 改写建议。 | 选择场景 → AI 开场 → 用户语音回答 → AI 续话 → 总结报告 |
| **P1** | **场景库 + 语料本** `/library` | 预置 ~200 句高频职场短句（含 Help-me 救命句）+ 用户从会议笔记导入的自建语料。 | 浏览、搜索、加入今日 Display 队列、加入跟读队列 |
| **后台** | **复习调度（SM-2）** | 自动从错题、卡壳句、生成今日复习队列。Display 和跟读都消费这个队列。 | 用户感知不到，但每天打开 Dashboard 看到的"今日复习 12 句"就是它产的。 |

**砍掉**：
- ❌ 30 天课程页
- ❌ 卡壳恢复（合并入对话模块的场景之一）
- ❌ 错题复习独立页（融入跟读 + Display）

## 4. "场景库 + 语料本"是核心创新

README 里的"卡壳恢复"和"会议表达"是好想法，但散落在不同页。我把它们整合成：

**预置场景库（V1 上线时人工写 ~200 句）**，分 5 类：
1. **緊急救命** — "少し考えさせてください" / "後ほど共有します" / "確認してから返信します"
2. **進捗報告** — "現時点では…" / "予定通り進んでいます" / "リスクが一点ございます"
3. **依頼・確認** — "もう一度お願いできますか" / "認識合わせをさせてください"
4. **謝罪・調整** — "申し訳ございませんが…" / "別途調整させていただきます"
5. **雑談・距離感** — "お疲れ様です" / "週末いかがでしたか"

**个人语料本**：
- 一个 "import" 入口：粘贴会议纪要 / Slack 对话 / 邮件原文 → Gemini 自动抽取里面的日语短句 + 给中文翻译 + 给关键词 tag
- 抽取出来的句子默认加入复习队列
- **这就是你的真实课程**

## 5. AI 集成的诚实约束

### Gemini 用在哪
- **自然度反馈**（输入：用户文本 + 原始中文意图；输出：改写建议、商务版、口语版）
- **场景对话续接**（输入：对话历史；输出：AI 的下一句日语 + 难度自适应提示）
- **语料抽取**（输入：用户粘贴的中日混排文本；输出：结构化的句子列表 + 翻译 + tag）

### Gemini 不能用在哪
- ❌ 评估发音（它看不到音频）
- ❌ 评估朗读语调 / 停顿（同上）
- ❌ 实时打分（延迟太高，体验差）

### 发音评估的真实方案
- **粗评分**：用 Google STT 的 `confidence` + 把识别结果和原句做 token 级 diff（WER）
- **细评估**：v2 再考虑接入 Azure Speech Service 的 Pronunciation Assessment API（它能给出 phoneme 级评分）
- **V1 就明确告诉用户**："发音评分 = STT 能否正确识别 + 是否漏字 + 是否多字"。这已经覆盖了 80% 的中国学习者发音问题（拗音、长音、促音）。

### 成本控制
- TTS：用 sentence_hash 当 key 做永久缓存。同一句话**永不重新合成**。
- STT：浏览器 Web Speech API 优先（免费，但精度差），Google STT 仅在用户开 "精确模式" 时调用。
- Gemini：每次 drill 评估缓存 24 小时（同一句中文同一个用户输入，反馈应该一致）。

> 预计月成本：Gemini API < $5，Google STT < $3（按每天 30 次精确模式估算），TTS 首月 < $2（首次合成）后续接近 0。**总月成本 ~$10**，远低于 Anki Pro 的订阅费。

## 6. 部署形态

- **域名**：自选（例：`nihongo.{你的域名}` 或 `study.{你的域名}`）。建议直接挂在已有的个人域名子域。
- **托管**：Vercel（免费 plan 够用）。
- **数据**：Supabase 免费 tier（500MB DB + 1GB storage 够用很久）。
- **录音备份**：Supabase Storage 直接存。可选 S3 冷备份（按月 cron）。
- **PWA**：必须支持。手机挂机 Display 模式必须能"添加到主屏幕 → 全屏运行"。

## 7. 不做什么（明确边界）

- ❌ 不做语法讲解 / 词典查询（你 N1 阅读，不需要）
- ❌ 不做汉字描红 / 手写练习
- ❌ 不做社区 / 排行榜 / 分享
- ❌ 不做 iOS / Android 原生 app（PWA 够了）
- ❌ 不做支付 / 订阅
- ❌ 不做 i18n 切换 UI 语言（UI 中文，学习目标是日语，固定就好）

## 8. 开发节奏建议

| 阶段 | 周期 | 交付 |
|---|---|---|
| **Phase 0 — 设计定稿** | 当前 | 三份 docs + 你 review |
| **Phase 1 — Display 屏 + 场景库** | 3-5 天 | 能在第二屏跑起来，预置 200 句立刻能用 |
| **Phase 2 — Drill + 跟读** | 1 周 | 接入 Gemini + STT/TTS，开始有真实学习数据 |
| **Phase 3 — 对话 + 语料本** | 1 周 | 完整 V1，开始日用 |
| **Phase 4 — 个性化** | 持续 | 根据使用日志调整算法、UI 微调 |

**关键原则**：Phase 1 上线后就开始日用。**不要追求"全部做完再用"**，那是 demo 思维。一个能用的 Display 屏 + 200 句预置场景，已经比你现在的零基线强 100 倍。

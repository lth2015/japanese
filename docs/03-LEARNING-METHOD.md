# 设计稿 03 — 学习方法论与系统整合

> 这份文档把"为什么这么训"和"系统怎么改"绑在一起。它会改写 [00-DESIGN.md](./00-DESIGN.md) 中的"V1 模块"，并新增字段到 [01-ARCHITECTURE.md](./01-ARCHITECTURE.md) 的数据模型。

## 1. 诊断：你卡在哪儿

你的能力曲线（你的自评，也是整代中国应试学习者的共性）：

```
读 ████████████░░░░   能默读考题；N1 偏难，N2 较流畅
写 ████████           会写邮件，但需要查字典
听 ████               语速一快就糊
说 ██                 看着对方眼睛大脑空白
```

**重要细化**（你 2026-05-14 的补充让我重新校准了诊断）：

你的"读"是**默读 + 考题式阅读**。这意味着：

- 你的**视觉识别**强（看到 確認 知道意思）
- 但你的**音义联结**弱（看到 確認 不一定立刻在脑里响起 かくにん）
- 你从未大规模"读出声"过日文——这导致**听力薄弱不是巧合**，是同一个根源：声音和字之间从未被反复连接过

**这不是天赋问题，是训练时数的极度倾斜 + 音义联结的缺失。**

- 你这辈子累计的输入时数（默读为主）保守估计 1500h+
- **大声朗读时数** + **听力专注时数** 加起来可能 < 50h
- 累计的输出时数（写 + 说）保守估计 < 100h

应试体系奖励"再认"（看出这个字、记得这个句型），不奖励"提取"（脑子里把意思组装成句子说出来），也**完全不奖励大声读**（考试不会让你朗读）。

**关键认知**：读、听、说是**三种不同的技能**，不是"读懂了就能说"。这是 SLA（二语习得）研究 50 年的共识，但应试教育从不教。你不缺日语知识，你缺的是**两个连接**：

1. **字 ↔ 声** 的联结（这是听力和朗读共享的根）
2. **意 → 输出** 的提取通路（这是说和写共享的根）

这两个连接才是你真正要训的，不是再多刷 N1 词汇。

## 2. 理论支撑（一段就够）

| 来源 | 核心论点 | 给你的启示 |
|---|---|---|
| **Krashen 输入假说** | 听 / 读 "i+1"（略高于当前水平）的内容是积累根本 | 你的 i+1 输入已经够了，下一步是逼输出 |
| **Swain 输出假说** | 只输入不够，**强制输出**才能把"模糊掌握"逼成"精确掌握" | 这是你的破局点 |
| **DeKeyser 技能习得理论** | 知识从"陈述性"（我知道这个）→ "程序性"（不假思索用）只能靠重复输出 | 解释了为什么你"知道"但"说不出"——你的知识从未程序化 |
| **Lewis 词块法** | 大脑不是按"语法 + 单词"造句的，而是调用**预制语块** | 重点不是学语法，是把 500 个高频块刻进肌肉记忆 |

**一句话**：你的破局点 = **强制输出 + 词块化**，不是更多输入。

## 3. 训练方法：R→W→**音読**→L→S 五阶通关

考虑到你"默读但不出声"的实际起点，原来 4 阶段不够。**必须插入"音読"作为 Stage 2.5**——这一关是修复"字↔声"联结的关键，跳过它你的听力永远好不了。

```
Stage 1 阅读理解（默读）        ← 你已经在这一关
   ↓
Stage 2 看中文写日文            ← 写：开始往输出过渡
   ↓
Stage 2.5 音読：看日文朗读出声    ← 新增 — 把"字"绑回"声"
   ↓
Stage 3 听日文写日文            ← 听写：把听力强行接到输出上
   ↓
Stage 4 看中文 5 秒内说出口      ← 即时口译：最重要的战场
   ↓
Stage 5 真实对话自然说出         ← 程序化：靠真实场景累积
```

### 关于 Stage 2.5「音読」（朗读）的具体设计

**为什么必须存在**：
- 母语者的内心声音（subvocalization）比阅读更快、更深刻地塑造语感
- 你读了 20 年默读，从未让"看见汉字"自动触发"听见声音"——所以 听力 = 听不见、说话 = 说不出来
- 让句子先从你**自己嘴里**出来，比直接听 TTS 更有效——这是"运动记忆 + 听觉反馈"双通道

**训练流程**：
1. 系统显示日文（带平假名标注：<ruby>確認<rt>かくにん</rt></ruby>）
2. 你**自己读出声**，录音
3. 系统播放 **TTS 标准发音**
4. 你**再读一次**，对比录音
5. STT 转写你的录音 → 字符级 diff
6. 评分：能识别 = 80分起步，韵律/节奏由 Gemini 听 transcript 给定性反馈

**关键规则**：Stage 2.5 通过 = 系统能识别你的朗读且无明显错读。**不要求像母语**——只要求"能被听懂"。

### 5 阶段的核心规则（不变）

1. **以最低阶段标识能力**。一句话停留在 Stage X，系统就只算你 Stage X。你的"已学 200 句"如果都在 Stage 2，那不是 200 句，是 0 句进入了实战。

2. **Stage 4 是核心战场**。5 秒约束逼你**不能"想中文 → 翻译 → 自我检查 → 输出"**——必须直接调用已成块的表达。这是把陈述性知识程序化的唯一路径。

3. **"通关"不是单次成功，是稳定性**。Stage 4 在不同时间命中 3 次（间隔 ≥1 天）才算锁定。失败一次降回上一级（Stage 3 或 Stage 2.5）。

4. **少而精胜过多而浅**。第一周宁可只锁 10 句到 Stage 4，也不要把 100 句过到 Stage 2。前者会改变你，后者只是"背完就忘"的循环。

## 4. 语料库扩展策略

V1 只有 44 句商务句。要扩到 **三种内容类型**：

| 类型 | 目标量 | 用途 |
|---|---|---|
| **单句词块** (`sentence`) | 500-800 句 | 高频商务表达 + 日常对话短句。所有 5 阶段训练的主体 |
| **多轮对话** (`dialogue`) | 50-100 段 | 模拟会议、1on1、Slack 对话。训练**接话能力** |
| **短文** (`passage`) | 30-50 篇 | 邮件模板、会议纪要、汇报片段。**用你最强的"读"作为新内容的入口** |

### 4.1 sentence 表新增字段（含 furigana 支持）

```ts
// lib/db/schema.ts 增量
tokens: jsonb            // ← furigana 渲染数据，详见下文
register: text           // "敬語" | "丁寧" | "カジュアル"
frequency_rank: integer  // 1-1000，使用频率（1=最常用）
chunk_pattern: text      // "...させてください"，可复用骨架
context_tags: text[]     // ["会议", "邮件", "Slack", "1on1", "日常"]
mora_count: integer      // 拍数（影响听写难度）
```

**关于 `tokens` 字段（furigana 渲染）**：

```jsonc
// "確認させてください" 拆成：
[
  { "text": "確認", "kana": "かくにん" },
  { "text": "させてください", "kana": null }
]
```

渲染：`<ruby>確認<rt>かくにん</rt></ruby>させてください`

为什么需要这个：你现在 SentenceCard 把假名作为单独一行显示（"確認させてください / かくにん させてください"），这适合识别但**不适合朗读训练**——你的眼睛会跳到下面那行直接读假名，跳过了"看汉字想发音"的关键步骤。**真正的 furigana ruby 标注是逐字配对的**，你的眼睛在汉字上停留时假名就在它上方，强迫"字↔声"建立连接。

`kana` 整句字段保留作为兜底（不是所有句子都需要 token 化），但**新增 / AI 生成的所有内容必须包含 tokens**。

### 4.2 新增 dialogue 表

```ts
dialogue: {
  id, title, scenario,                  // "1on1 进度延期"
  turns: jsonb                          // [{speaker: "上司"|"你", text, tokens, kana}]
  difficulty, register, context_tags
}
```

### 4.3 新增 passage 表

```ts
passage: {
  id, title, source,                    // "周会汇报邮件" / "项目延期说明"
  body: text,                           // 含 tokens 的富文本
  vocabulary: jsonb,                    // [{word, kana, meaning}] 高亮词
  questions: jsonb,                     // [{q, a, type}] 阅读理解
  difficulty, length_words
}
```

### 4.4 新增 user_progress 表（每用户对每句子的 stage 状态）

```ts
{
  sentenceId
  currentStage           // 1-5（含 2.5 = 25 内部存储）
  stageHistory: jsonb    // [{stage, passedAt, score}, ...]
  stage_X_attempts       // 各阶段最近 3 次成绩
  nextReviewAt
  easeFactor
}
```

### 4.5 入库来源（四路并进，去掉"工作时粘贴"的依赖）

| 来源 | 类型 | 占比 | 怎么来 |
|---|---|---|---|
| **人工种子库** | 单句 + 对话 + 短文 | 30% | 我从 ビジネス日本語決まり文句、JLPT N2/N1 商务高频、NHK 简易新闻整理 |
| **AI 批量生成** | 单句 + 对话 + 短文 | 40% | Gemini 按场景批量生成 → 我帮你 review 标 frequency_rank |
| **AI 出题（动态）** | 写作题 + 翻译题 + 阅读理解 | 持续 | 每次打开 /drill 系统按你薄弱处生成新题；通过的题入库 |
| **你自己编织** | 单句 + 短文 | 20% | 晚上你写"今天遇到的情景" / 自己编一篇短文 → 入库 + AI 标注 furigana + 出复习题 |

> **重要变化**：**完全删除了"工作时粘贴会议笔记"这条路径**——你说过工作时不方便传给我。改为**晚上 jot 模式**（你写中文情境描述，AI 生成对应日语），以及**自编 + AI 协作**的内容生产方式。这反而更可控、更符合你"愿意自己写"的偏好。

## 5. 系统改造（具体到 PR 级别）

### 5.1 新增页面 / 模式

| 路径 | Stage | 用途 |
|---|---|---|
| `/drill` | Stage 2 | 看中文输入日文（已设计）|
| `/read-aloud` | **Stage 2.5** | **音読**：看带 furigana 的日文 → 朗读 → STT 校对 → TTS 对比 |
| `/listen-write` | Stage 3 | **听写模式**：不显示文字，TTS 播放，你打字。听完一次可重听 2 次 |
| `/quick-fire` | Stage 4 | **5 秒即时口译**：中文出现 → 5 秒倒计时 → 录音 → 通过则升 Stage |
| `/shadow` | Stage 4 辅助 | **影子复述**：TTS 播放**同时**你跟读（不是听完再说），训练听说同步 |
| `/passages` | 阅读+输出 | **短文模式**：用你的"读"强项做入口——读完一篇短文 → 回答问题 / 写改写 / 总结要点 |
| `/exercises` | 综合 | **AI 出题**：系统按你薄弱处自动生成新题；通过的题入复习队列 |
| `/jot` | 实战导入 | **晚上情境登记**：你写中文（"今天上司问我进度，我说不出来"）→ AI 生成日语 → 入库 |
| `/prep` | 实战 | **会前 15 分钟 prep**：给一个主题 / 议程关键词 → AI 生成 10-15 句可能要说的 → 即时 drill |
| `/today` | 实战 | **今日 5 分钟独白**：录 60 秒"今天我做了什么"，Gemini 转写 + 改写自然版，存档历史对比 |

替换当前的本周统计区。一眼看到你**真正的进度**：

```
你的词块库（共 287 句）
─────────────────────────────────────
Stage 1 (能识别)     ████████████████░░░░  82%
Stage 2 (能写出)     ████████░░░░░░░░░░░░  38%

Stage 5 (实战命中)   □                       0%

   预计 15 分钟。完成后你的"听写命中" 14% → 18%。
```

**关键设计**：把 Stage 4 醒目高亮——那才是"真实战斗力"指标。让你**永远看见现实**，不被 Stage 1/2 的虚高数字麻痹。

### 5.3 Display 模式扩展：Shadow Sub-mode

Display 不仅是"看 + 听"。新增 **跟读侦测**：
- 句子显示后 TTS 自动播放
- 麦克风启用监听 0.5-2s 窗口
- 检测到语音活动 → 标记本次 shadow 命中（不要求识别正确，只要"你张了嘴"）
- 长期累积：你**坐在副屏旁边的工作时间** = 隐形的 shadow 时间

这是最低门槛的输出训练。你边写代码边随口跟读两句，一周累积 100+ 次张嘴。**张嘴本身就是肌肉训练**。

### 5.4 复习算法：按 Stage 调度

SM-2 不按"句子"复习，按"句子 × Stage"复习：

- Stage 2 通过 → 2 天后排 Stage 2.5（音読）任务
- Stage 2.5 通过 → 3 天后排 Stage 3 任务
- Stage 3 通过 → 7 天后排 Stage 4 任务
- Stage 4 通过 → 进入长期间隔（14d → 30d → 60d）
- 任一 Stage 失败 → 降一级，从那级重新爬

### 5.5 出题模式（/exercises）

不是从语料库挑题，是 **AI 实时为你生成新题**。这是为了应对你的核心约束：工作时不能粘贴 + 自己想造句太累。

**题型库**：

| 题型 | 输入 | 输出 |
|---|---|---|
| **看中文写日文**（drill 子集）| Gemini 给一句新中文 | 你写日文 → 评估 |
| **改写体**（敬→常 / 常→敬）| 给你一句 カジュアル | 改成 敬語 |
| **续写对话** | 给一个对话片段 + 上司最后一句 | 写你的回应 |
| **缩写邮件** | 给一封 200 字商务邮件 | 缩写成 50 字 Slack 消息 |
| **阅读理解写答案** | 给一篇短文 | 用日语回答 3 个问题（强迫输出，不是选择题）|
| **改错** | 给一句故意写错的（你常犯的错型）| 改对并说理由 |

**AI 出题 prompt 结构**：

```
SYSTEM:
学习者画像：N2 流畅 / N1 在学，目标日企会议产出。已掌握 {topics} 主题。
当前薄弱：{weak_categories}（系统从历史数据传入）

请生成 1 道 {exercise_type} 题。
要求：
- 难度紧贴学习者当前水平（i+1）
- 用真实工作场景，不要教科书味
- 不要包含答案
- 输出 JSON: { prompt, expectedFeatures, idealAnswers: [...3个不同版本], rubric }

USER:
（learner-provided context if any, otherwise empty）
```

**关键**：出题题目本身**也会进语料库**（如果你通过了），下次它就是 sentence 表里的一条。系统在用你的练习数据自我进化。

**关键**：你今天通过 Stage 4 的句子，**不会马上从复习队列消失**。它会以更长间隔回来，确保你不会"赢了又输"。

### 5.5 反馈系统的两个非常规设计

1. **流畅度优先于正确度**（前 4 周）。
   - Quick-Fire 评分公式：`score = 60% * 流畅度 + 40% * 准确度`
   - 流畅度 = 5 秒内是否开口；不卡壳；嗯啊词少
   - 4 周后再切换为 50/50。
   - 这违反应试直觉，但这是把你从"完美主义瘫痪"中拉出来的唯一方式。

2. **错误不扣分，沉默扣分**。
   - 5 秒没说话 = 0 分。说了错的 = 至少 40 分。
   - 说明：你过去 20 年的教育已经把"宁可不说也不要说错"刻进你的骨髓。系统必须反过来奖励"说"。

## 6. 第一周：你能马上看见效果的路线图

**目标：第 7 天能在镜子前 5 秒内说出 20 个高频救命句而不卡。**

> 数字从原来的 30 句下调到 20——加入 音読 这个新阶段会更慢，但每句留下的痕迹更深。

| 天 | 任务 | 预计时间 | 你会发现的事 |
|---|---|---|---|
| Day 1 | Stage 2（看中文写日文）跑 25 句 | 25 分钟 | 你以为都会，结果 80% 写出来了，剩 20% 卡壳——这就是"识别 vs 提取"的差距 |
| Day 2 | Day 1 通过的 25 句 → **Stage 2.5（音読）** | 25 分钟 | 第一次大声读日文。你会发现某些字你"知道意思但读不出来"——比如 進捗 是 しんちょく 还是 しんしょく。**这就是音义联结的洞** |
| Day 3 | Stage 2.5 通过的 ~18 句 → Stage 3（听写）| 30 分钟 | 因为前一天朗读过，听写比直接听写好一点——这就是 Stage 2.5 的价值。能默写出 12-15 句 |
| Day 4 | Stage 3 通过的 12-15 句 → Stage 4（5 秒即时口译）| 25 分钟 | 可能只剩 7-10 句。**这就是你的"真实日语战斗力"基线**。承认它，然后从这里起步 |
| Day 5-6 | 反复打磨这 7-10 句的 Stage 4 + 加 5 句新的 Stage 2 起步 | 每天 20 分钟 | "程序化"开始发生——某些句子开始不假思索从嘴里出来 |
| Day 7 | 在镜子前对自己模拟晨会汇报，用这 7-10 句 + 浏览 1 篇短文 | 10 分钟实操 | 神奇时刻：第一次"不卡"地说出整段日语 |

第二周开始引入 **/prep 模式**：晚上想想"明天有什么场合"，输入主题（不需要粘贴细节），drill 出来的句子直接用在第二天的会上。这是**学习闭环**：学了 → 用了 → 又学新的。

## 8. 三件你需要心理准备的事

1. **第一周会很挫败**。Stage 3 / Stage 4 的塌方是设计的——它在**给你看真实位置**。这不是系统坏了，是 20 年的应试输入终于在系统的镜子里被照出来了。**这是好事**。

2. **每天 25 分钟比每周末 3 小时有效 10 倍**。SLA 研究：分散式练习对程序化记忆的效率，是集中式的 5-10 倍。每天打开系统一次比"周末补课"重要。

3. **N1 证书和能说话没关系**。承认这一点的人会进步，否认的人继续在原地。你已经承认了——这就是你和 90% 卡在这里的人最大的差别。
